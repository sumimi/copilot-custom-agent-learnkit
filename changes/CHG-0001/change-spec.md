# 変更仕様書: CHG-0001

## 1. 目的

ユーザー登録時に空のユーザー名を受け付けないようにし、不正なユーザーデータがリポジトリへ登録されることを防止する。

## 2. 変更要求

### CR-001: 空のユーザー名を拒否する

`UserService::register_user` に空文字列が渡された場合、ユーザーを生成またはリポジトリへ登録してはならない。

### CR-002: 呼び出し側へ失敗を通知する

空のユーザー名を拒否した場合、`UserService::register_user` は呼び出し側が判定できる形で失敗を通知する。

失敗通知の方法は設計フェーズで決定すること。候補には例外、戻り値の変更、エラー型の導入がある。

### CR-003: 既存の正常系動作を維持する

空でないユーザー名による登録では、従来どおり `User` を生成し、メールアドレスを `<name>@example.com` としてリポジトリへ登録する。

## 3. 制約

- `UserService` は引き続き `IUserRepository` に依存する。
- `UserRepository` の具体的な保存方式は変更しない。
- 認証、認可、メールアドレス形式の検証は対象外とする。
- 空白だけの文字列の扱い、ユーザー名の長さ制限、重複ユーザー名の検出は対象外とする。
- C++17 の既存規約に従う。
- ソースコードとユニットテストの変更は、設計レビュー承認後に実施する。

## 4. 受入条件

- 空文字列を指定した登録がリポジトリを呼び出さない。
- 空文字列を指定した登録の失敗を呼び出し側が判定できる。
- 空でないユーザー名の登録が従来どおり動作する。
- 空文字列に関するユニットテストが追加される。
- 既存の `UserService` テストがすべて成功する。
- API 契約、エラー処理、テスト方針が設計書へ反映される。

## 5. 設計書への反映

本変更では、設計書の以下を更新する。

- `UserService::register_user` の入力検証契約
- 空のユーザー名に対するエラー契約
- `AppController` へのエラー伝播方針
- 正常系・異常系ユニットテストの対応

## 6. 対象外

- 空白だけの文字列の扱い
- ユーザー名の長さ制限
- メールアドレスの検証
- 重複ユーザー名の検出
- PostgreSQL への永続化
